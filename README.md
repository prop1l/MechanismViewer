# MechanismViewer

Подбор механизмов под заданные параметры с 3D-демонстрацией их работы.

Пользователь описывает задачу: какое движение нужно получить, с каким ходом, углом или передаточным числом, под какой нагрузкой, в каких габаритах и от какого привода. Приложение находит подходящие механизмы в каталоге, объясняет, насколько каждый подходит, и показывает выбранный в работе: механизм с мотором крутится сам, рычаг тянут мышью, кнопку нажимают.

**Стек:** C# · .NET 10 · WPF · [HelixToolkit.Wpf](https://github.com/helix-toolkit/helix-toolkit) · xUnit

![Четырёхзвенник в работе: слева поиск, в центре модель, справа спецификация крепежа](docs/screenshots/four-bar-running.png)

## Возможности

- **Каталог с миниатюрами.** Слева — все механизмы по категориям: 3D-миниатюра, движение с главным параметром (ход, угол, передаточное число) и привод. Быстрый фильтр ищет по названию, категории и описанию с учётом окончаний («рейка» найдёт и «рейкой»); ◀ ▶ или Ctrl+←/→ — соседний механизм.
- **Подбор по параметрам.** Учитываются вид движения на входе и выходе, передаточное число, ход, угол поворота, момент или усилие нагрузки, скорость, габариты (в любой ориентации) и тип привода.
  - Механизмы, не выполняющие жёсткие требования, отсеиваются с объяснением причины.
  - Остальные получают оценку 0–100 % и пояснения: «ход 23,6 мм (нужно 25 мм, −6 %)», «малый запас по усилию ×1,1».
- **3D-демонстрация с физикой.** У каждого механизма одна степень свободы, физика учитывает инерцию, трение, нагрузку на выходе и упоры.
  - **Мотор** — двигатель постоянного тока с ПИ-регулятором скорости. Показываются напряжение, ток, момент, мощность и застопоривание.
  - **Рычаг или ручка** — деталь тянут левой кнопкой мыши; усилие руки ограничено.
  - **Кнопка** — нажимается, пока зажата кнопка мыши, и возвращается пружиной.
- **Крепёж и спецификация.** Винты, саморезы, штифты и стопорные кольца строятся процедурно по стандартам (ISO 4762, ISO 7049, ISO 4026, ISO 2338, DIN 471). Выбор строки спецификации подсвечивает элемент в сцене.
- **Каталог расширяется без кода:** механизм — это папка с `mechanism.json`. Простые детали описываются в нём же примитивами (`shape`) и строятся при открытии, STL нужен только для моделей из CAD.

## Быстрый старт

Нужны Windows и [.NET 10 SDK](https://dotnet.microsoft.com/download).

```powershell
git clone https://github.com/prop1l/MechanismViewer.git
cd MechanismViewer
dotnet run --project MechanismViewer
```

Решение `MechanismViewer.slnx` открывается и в Visual Studio.

| Команда | Что делает |
|---|---|
| `dotnet build MechanismViewer.slnx` | Собрать приложение и тесты |
| `dotnet test MechanismViewer.Tests` | Запустить тесты |

## Как устроено

```
mechanism.json ──► CatalogLoader ──► MechanismDefinition
                                       │
          ┌────────────────────────────┼─────────────────────────┐
          ▼                            ▼                         ▼
   MechanismSearch            KinematicSolver              MechanismScene
   (фильтры + оценка)   (q → положения деталей, k = dq_i/dq)  (shape/STL, шатуны, крепёж)
                                       │                         ▲
                                       ▼                         │
                              MechanismSimulator ───── координаты деталей
                        (мотор или рука, пружина, упоры,   каждые 16 мс
                         приведённая инерция J(q), шаг 1/480 с)
```

| Папка | Содержимое |
|---|---|
| `MechanismViewer/Catalog/` | Формат описания, загрузчик и сами механизмы (`<id>/mechanism.json`, STL — только для CAD-деталей) |
| `MechanismViewer/Kinematics/` | Решатель и связи: `gear`, `rack`, `screw`, `crank-slider`, `four-bar`, `cam`, `geneva` |
| `MechanismViewer/Physics/` | Симулятор механизма, модель мотора, параметры подвижных деталей |
| `MechanismViewer/Interaction/` | Приводы: мотор, перетаскивание рычага или ручки, кнопка |
| `MechanismViewer/Search/` | Запрос, поиск и оценка, карточки результатов |
| `MechanismViewer/Visuals/` | Сцена, построение деталей по `shape`, кэш сеток, процедурный крепёж, модель мотора, свободная камера |
| `MechanismViewer.Tests/` | Тесты xUnit |

Механизм рассматривается как система с одной степенью свободы: координата ведущей детали `q` однозначно задаёт положения остальных через цепочку связей. Динамика решается для приведённых параметров J(q) = Σ Jᵢ·kᵢ², b(q) = Σ bᵢ·kᵢ², поэтому рычажные, кулачковые и мальтийские механизмы с переменным передаточным отношением считаются тем же кодом, что и зубчатая пара. Ток мотора, вязкое трение и пружины интегрируются неявно, сухое трение — явно, с залипанием.

Сетки деталей хранит `MeshCache`. Каждая сетка строится или читается из STL один раз и замораживается. Ключ кэша — хеш содержимого файла или описания `shape`, поэтому одинаковые детали (две шестерни пары, одинаковые кривошипы разных механизмов, повторное открытие) делят одну сетку, а материал у каждой детали свой, для подсветки. Ссылки в кэше слабые: сетки закрытого механизма освобождаются сборщиком мусора.

## Добавление механизма

1. Создать папку `MechanismViewer/Catalog/<id>/`.
2. Описать форму каждой детали в её собственной системе координат: ось шарнира проходит через начало координат, единицы — мм. Шатун или тяга строится от первой шарнирной точки вдоль +X. Простые детали задаются списком примитивов `shape` (таблица ниже), модели из CAD — файлом `stl` рядом с `mechanism.json`.
3. Описать механизм в `mechanism.json`:

```jsonc
{
  "id": "crank-slider-15-50",
  "name": "Кривошипно-ползунный механизм 15/50",
  "category": "Рычажные механизмы",
  "motion": { "input": "rotation", "output": "linear" },   // rotation | linear | oscillation | intermittent
  "specs": { "strokeMm": 30, "maxForceN": 0.4, "maxSpeedRadS": 20 },
  "envelopeMm": [105, 50, 60],
  "driver": { "type": "motor", "part": "crank", "motorGapMm": 6.0 },  // motor | lever | crank | button
  "output": "slider",
  "parts": [
    { "id": "crank", "color": "#4682B4",
      "shape": [
        { "cylinder": { "r": 6, "z": [0, 5] } },                         // ступица
        { "box": [0, -4, 0, 15, 4, 5] },                                 // плечо
        { "cylinder": { "at": [15, 0], "r": 2, "z": [5, 10], "segments": 24 } }  // палец
      ],
      "joint": { "type": "revolute", "origin": [0, 0, 0], "axis": [0, 0, 1], "phase": 0 },
      "inertiaKgM2": 1.6e-7 },
    { "id": "slider", "color": "#FFA500", "shape": [ { "box": [-9, -7, 10, 9, 7, 18] } ],
      "joint": { "type": "prismatic", "origin": [65, 0, 0], "axis": [1, 0, 0] },
      "massKg": 0.0031 },
    { "id": "rod", "shape": [ { "box": [0, -2.5, 5.5, 50, 2.5, 9] } ],
      "joint": { "type": "link", "axis": [0, 0, 1],
                 "link": { "from": "crank", "fromPoint": [15, 0, 0], "to": "slider", "toPoint": [0, 0, 0] } } },
    { "id": "guide", "stl": "Guide.stl" }                    // без joint — неподвижная деталь; форма из CAD
  ],
  "couplings": [
    { "type": "crank-slider", "from": "crank", "to": "slider", "crankMm": 15, "rodMm": 50 }
  ],
  "fasteners": [
    { "kind": "Винт крепления направляющих", "size": "M3×8", "type": "socket-screw",
      "diameterMm": 3, "lengthMm": 8, "positions": [[30, 4.5, 2], [80, 4.5, 2]],
      "axis": [0, 0, -1], "attachedTo": "guide" }
  ]
}
```

4. Запустить `dotnet test MechanismViewer.Tests`. Тест `EveryCatalogEntry_BuildsAndRuns` сам подхватит новый механизм и проверит, что он загружается и движется. Тест `PartsDoNotPassThroughEachOther` проведёт его по всему ходу и сообщит, какие детали, крепёж или мотор проходят друг сквозь друга и где.

| Связь | Шарниры | Параметры |
|---|---|---|
| `gear` | вращение → вращение | `ratio` (по умолчанию −z₁/z₂ по `gear.teeth`) |
| `rack` | вращение ⇄ сдвиг | `radiusMm` (по умолчанию радиус шестерни) |
| `screw` | вращение → сдвиг | `leadMm`, знак задаёт направление |
| `crank-slider` | вращение → сдвиг | `crankMm`, `rodMm`, `offsetMm` |
| `four-bar` | вращение → вращение | `crankMm`, `couplerMm`, `rockerMm`, `branch`. Начальный угол коромысла (`phase`) должен совпадать с геометрией — решатель это проверяет и сообщает верное значение |
| `cam` | вращение → сдвиг | `segments`: участки `angleDeg`, `riseMm`, `law` (`cycloidal` / `harmonic`) |
| `geneva` | вращение → вращение | `slots` |

| Примитив `shape` | Что строит |
|---|---|
| `box: [x0, y0, z0, x1, y1, z1]` | Параллелепипед |
| `cylinder: { at, r, z: [от, до], segments }` | Цилиндр с осью Z |
| `polygon: { points: [[x, y], …], z }` | Простой многоугольник, выдавленный по Z |
| `gear: { at, module, teeth, phaseDeg, z }` | Прямозубое колесо: трапециевидный зуб 20° с боковым зазором, первый зуб на `phaseDeg` |
| `rack: { origin, direction, module, teeth: [k₀, k₁], z }` | Зубья рейки на делительной прямой, зуб k — на k·π·m |
| `thread: { r: [впадина, вершина], pitch, z, width: [у впадины, у вершины] }` | Правая резьба вокруг Z |
| `ringX: { x: [от, до], r: [внутр., наружн.] }` | Кольцо вокруг оси X (виток пружины) |
| `cam: { z }` | Контур кулачка под плоский толкатель по закону связи `cam` этой детали |
| `genevaStar` / `genevaDisk: { slots, centerDistance, slotWidth, pinRadius, z }` | Мальтийский крест / запирающий диск ведущего звена |

`shapeAxis: "x"` выдавливает форму вдоль X вместо Z (колесо червячной пары, зеркальный перенос). `shapeAxis: "y"` поворачивает форму осью вверх — так строятся вертикальный винт, столик и основание подъёмного столика; резьба при повороте остаётся правой.

Для ручных приводов в `driver` задаются `range` (упоры, ° или мм), `handForce` (предельное усилие руки, Н·м или Н) и `spring` (возвратная пружина). Для мотора можно включить `reverseAtLimits`, задать `hubSeatMm` (торец ведущей детали, к которому её прижимает ступица мотора, по умолчанию 10 мм) или `shaftEndMm` (вал кончается внутри ступицы детали, ступицы мотора нет — для кривошипов, над которыми ходят шатуны).

## Ограничения

- Механизмы только с одной степенью свободы и без замкнутых контуров: каждая деталь получает движение по одной связи.
- КПД винтовых и червячных передач не моделируется, учитывается только трение. Масса шатунов и пружин не учитывается.
- Ось мотора, четырёхзвенника и мальтийского креста должна идти вдоль Z.
- Детали большинства механизмов — заготовки из простых тел. Зацепление червяка с колесом показано приблизительно.
